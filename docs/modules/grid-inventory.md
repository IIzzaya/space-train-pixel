# 网格库存

本模块说明主仓库、出行背包、物品占格和装备替换。机器输入输出采用独立规则，见[基地生产](production.md)。

## 库存对象

| 对象 | 已确认用途 | 边界 |
| --- | --- | --- |
| 主仓库 | 玩家在基地保管和整理物品的网格仓库 | 尺寸、扩容和堆叠规则尚未确定 |
| 出行背包 | 外出携带装备、补给和战利品的网格容器 | 背包型号具有不同容量 |
| 装备槽 | 保存当前穿戴或使用的装备 | 槽位结构和锁定粒度尚未确定 |
| 背包物品 | 背包本体作为库存物品时的形态 | 占格与容纳容量分开，不形成嵌套容器 |
| 机器输入输出 | 机器各自保存原料与产物的区域 | 同类物品限量堆叠，规则独立于主仓库 |

## 初期拾取规则

1. 系统按发现顺序处理新战利品。
2. 新物品放得下时，系统把它装入背包。
3. 新物品放不下时，系统丢弃新物品或把它留在原地。

初期不以新战利品替换背包内的旧物品。价值替换、喜爱物品锁定和类别优先级属于后续成长方向。

【待确认：放置顺序、旋转、空间重排和形状可容纳性的判定算法。】

格子总面积足够，不一定表示物品可以放入。文档尚未指定自动装箱算法。

## 装备替换与锁定

未锁定装备遇到更好的装备时，可能被系统概率性替换。玩家可以锁定装备槽或已装备物品，避免主动替换；具体粒度尚未确定。

初期换下的旧装备可以直接丢弃。装备替换不改变“新战利品放不下就放弃”的基础拾取规则。

装备锁定不提供失败保护。外出失败时，锁定装备仍适用此次出行全损规则。

## 更换背包

系统更换背包时，必须保持全部原有内容。当前规则按以下顺序理解：

1. 系统判断原有全部内容是否能放入新背包。
2. 如果全部内容能放入，系统迁移全部内容并更换背包。
3. 如果无法全部放入，系统跳过换包并保持原状态。

初期成功换包时，只丢弃旧背包本体，不丢弃原有内容。系统不采用“迁移一部分，再丢弃其余内容”的方式。

以上是规则顺序，不是已经选定的事务、动画或算法实现。迁移是否允许旋转和重新排布仍待确认。

## 背包容量与本体占格

背包容纳容量和背包本体占格由不同属性表示。背包作为物品的占格由配置手工确定。

已确认的简化尺寸规则：把背包容量的两个尺寸分别除以 2，再向上取整。

| 容纳容量示例 | 本体占格示例 |
| --- | --- |
| 3×3 格 | 2×2 格 |
| 6×6 格 | 3×3 格 |

这两个例子说明尺寸关系，不是已经完成的背包型号表。

后续基地升级可以允许回收换下的旧背包，把旧背包本体装入新背包。回收的背包只是一个物品，不再提供内层存储空间。当前方向不采用嵌套容器或无限套包。

【待确认：旧背包回收升级的解锁方式，以及新包容纳旧包本体的检查顺序。】

## 补给和物品转换

| 物品 | 已确认占格 | 关联规则 |
| --- | --- | --- |
| 塑料废料 | 1×1 格 | 可用于生产瓶装水 |
| 瓶装水 | 1×2 格 | 饮用后留下 1×1 格塑料废料 |
| 生土豆 | 1×1 格 | 可以食用，也可以烘烤 |
| 烤土豆 | 1×1 格 | 恢复的饱食度多于生土豆 |

使用物品后的替换落格、旋转和堆叠尚未确定。不能把所有消耗品统一处理为“用完后整个物品消失”。

## 回仓整理

角色带着战利品返回后，玩家手动把背包内容转移到主仓库。这是核心整理体验的一部分。

【待确认：主仓库已满时的界面和处理方式，以及整理操作中的拖放、旋转和撤销规则。】

整理库存时，普通游戏时钟通常持续运行。真时模式等明确暂停条件除外；打开库存本身不会自动暂停。
