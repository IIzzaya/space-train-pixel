# 游戏设计总览

## 项目方向

本项目是一款以界面为主的静态 Web 前端游戏。玩家整理网格库存，准备外出装备，运行基地生产，并通过搜刮和增量升级逐步成长。

探索采用快速、自动推进的 idle 体验。玩家的主要决策发生在出发前和归来后。探索过程中，系统展示文字进程、随机事件和结果，不要求玩家逐个事件作出选择。

## 核心循环

以下流程描述已确认的设计关系，不是已实现的操作教程。

1. 玩家在基地整理主仓库，管理设施和生产物资。
2. 玩家选择武器、补给和背包等出行装备。
3. 玩家选择已解锁、可探索的地点后出发。
4. 系统自动推演探索、事件、拾取和角色状态。
5. 系统结算归来结果；失败时执行此次出行全损。
6. 玩家手动把带回的战利品转移到主仓库。
7. 玩家用积累的物资继续生产、配装和成长。

外出可能带回战利品，也可能发生其他特殊结局。特殊结局的类型和概率尚未确定。

## 已确认的设计支点

### 网格空间参与决策

背包容量和物品占格影响可携带的装备、补给与战利品。初期拾取按发现顺序装包，放不下的新物品留在原地。回到基地后，玩家手动整理战利品。

背包物品和背包容器是两个概念。更换背包时，系统必须迁移全部原有内容；无法全部放入时，跳过换包。具体规则见[网格库存](modules/grid-inventory.md)。

### 外出有损失与重新积累的路径

外出失败后，此次出行的全部装备和物品丢失。角色以低生命值返回。装备锁定不提供损失保护。

玩家可以用最低限度或廉价装备探索低级地点，重新获取背包、装备和枪械。该方向不保证每次成功，也没有确定免费装备或固定收益。

### 基地生产依赖持续投入

前两条生产线依次为食物和水。土豆栽培消耗肥料，水生产消耗塑料废料，初级烤炉通过共享热量获得加工能源。

机器拥有各自的输入和输出区域。同类物品在机器内可以限量堆叠。主仓库没有被选为机器直接供料与回收产物的统一区域。自动搬运尚未确定。

### 普通时间与真时分开

基地通常持续推进普通游戏时钟，整理库存和配装不会自动暂停。最低速度为 1×，即 1 现实秒对应 1 游戏秒。

离线经过的现实时间用于积累可储存的“真时”。玩家在线消耗真时时，普通游戏时钟完全暂停，列车生产独立推进。真时不直接恢复角色状态。

## 参考作品的使用范围

| 参考 | 本项目采用的方向 | 没有据此确定的内容 |
| --- | --- | --- |
| 《逃离塔科夫》 | 网格整理、出行配装、搜刮与装备损失体验 | 多人服务器、玩家对战、完整战斗或经济系统 |
| 《60 Seconds》 | 文字式外出进程和结果呈现的大致形式 | 家庭成员、原作时间规则或完整生存系统 |
| idle 与增量游戏 | 快速自动模拟、长期升级、真时资源 | 固定外出时长、全部自动化或现实付费 |

## 列车题材与范围边界

基地可能是一辆跨维度列车，在混乱的世界之间迁移。列车扩建、时空乱流、地图刷新和居民系统保留为后续讨论方向。

本文沿用“列车生产”描述真时作用范围。这个名称不表示列车迁移、风暴和居民系统已全部进入首版。

完整设想见[成长与后续方向](modules/progression-future.md)。当前首版范围尚未确定。
