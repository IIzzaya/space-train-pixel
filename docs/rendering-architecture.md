# 全画布渲染架构 · 0.3

## 正常图形路径

游戏只挂载一个可见 `<canvas>`。HTML/CSS 负责页面背景、画布尺寸与启动／图形错误提示，不承载仓库、日志、按钮、弹窗或拖拽层。

1. `scene.ts` 创建原创 Three.js 体素列车、环境和物品模型。
2. `renderer.ts` 使用单一 `WebGLRenderer`，先将列车场景渲染到 622×109 的 `WebGLRenderTarget`，再把该纹理贴到 HUD 场景的平面。正交相机按目标比例建立视锥，避免拉伸。
3. `ui.ts` 将仓库格、物品、进度条、按钮、日志、拖拽轮廓和模态框构建成 HUD 中的 `PlaneGeometry` / `MeshBasicMaterial`。文本先绘入离屏 CanvasTexture，然后也以 Three.js 平面进入同一场景。可见的游戏画面最终统一由 Three.js 合成到 1280×860 帧缓冲区。
4. 七种物品图标来自 Three.js 原创模型，经 SVGRenderer 烘焙为透明纹理，旋转图标与占格方向同步。没有可见的独立 SVG、Canvas2D HUD 或 HTML 控件。

英文像素字体加载完成后才生成文字纹理。面片池复用几何与材质；常用文字纹理缓存，计时／日志产生的旧纹理定期释放。输出使用最近邻放大；中文使用本机 CJK 字体，追求可读性而非把系统字体冒充像素字库。

## 无 WebGL 的兼容路径

GPU Disabled 环境中，`SVGRenderer` 投影相同的 Three.js 列车和图标。离屏 SVG 被栅格化为世界纹理；软件适配器投影相同的 HUD Mesh 矩阵，并读取它们的 CanvasTexture 写入同一个可见画布。仍没有 DOM 游戏界面。

该模式在画布右下角明确显示“软件兼容渲染”，`canvas.dataset.renderer` 为 `software`。软件 HUD 最多 10 FPS，世界更新约 1.3 FPS；WebGL 路径最多 30 FPS。可以用 `?renderer=software` 主动测试兼容路径。软件适配器不是 GPU WebGL 验收，也不声称所有像素经过 WebGL。若软件栅格化失败，画布显示失败状态；完全无法建立图形上下文时只显示非游戏错误说明。

## 输入与状态

- `types.ts` 定义物品、库存、机器、日志及游戏状态的显式类型。
- `engine.ts` 是纯 TypeScript 游戏规则；既有 v2 存储键与格式保持不变，反序列化从 unknown 逐字段校验。
- `input.ts` 处理 CSS 坐标 → 固定逻辑坐标、网格／物品命中、抓取格偏移、旋转和投放预览。坐标换算只使用画布实际边界，不重复乘 DPR；右／下边界不包含。
- 拖拽保存物品快照，预览不会改库存。只有有效 pointerup 经 `engine.move` 原子提交。碰撞、越界、Esc、pointercancel、lostpointercapture、失焦、尺寸变化或打开菜单取消事务。
- `main.ts` 管理单一画布的 pointer capture、键盘焦点、生产／探索时钟和本地保存。按钮的视觉与命中来自同一注册表；模态框打开时注册表只保留模态控件。实际修改操作仍检查当前游戏阶段，不能依赖上一帧按钮颜色。
- Tab / Shift+Tab 切换画布内控件，Enter / 空格激活；R 旋转；Esc 取消／关闭。日志支持滚轮、方向键、较新／较早按钮。键盘提供快捷转移，没有实现键盘精确格位摆放。

## 暂停与边界

页面隐藏、窗口失焦、菜单打开时，生产／探索／世界动画暂停；没有离线生产。图形上下文丢失时保存并停止游戏，恢复后重新载入。

布局面向桌面和平板横向视口；小屏按统一比例缩放，支持浏览器放大，不声称已完成手机触屏易用性验收。Canvas 具备键盘入口与说明，但尚未建立逐控件屏幕阅读器语义层，不能称为完整可访问性实现。
