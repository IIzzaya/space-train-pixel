本页说明设计文档的读者、状态标记和维护方式。文档用于支持设计、开发和测试协作，不是已完成产品的操作手册。

| 正本形式 | 仓库中的 Markdown 文档 |

## 状态标记

| 标记 | 含义 | 不包含的承诺 |
| --- | --- | --- |
| 已确认 | 设计规则或方向已确认 | 不等于已实现，也不自动进入首版 |
| 暂定示例 | 用于解释关系的数值或例子 | 不作为最终平衡配置 |
| 后续方向 | 保留的成长或扩展设想 | 不表示已批准开发排期 |
| 待确认 | 缺少规则、参数或范围决定 | 不允许用猜测补成默认行为 |
| 实现建议 | 为未来开发提出的候选方案 | 不表示技术选型完成或可行性已验证 |

缺口统一写成 `【待确认：具体问题】`。模块正文保留必要边界，[待确认问题](open-questions.md)集中列出问题。

## 维护流程

已约定的协作顺序是：模块讨论成熟后，先更新可见文档，再继续下一项细节。

文档维护时按以下顺序核对：

1. 更新对应模块，保留确认范围和未决条件。
2. 更新[设计决定](decisions.md)，记录新决定和被替代的旧方案。
3. 更新[待确认问题](open-questions.md)，移除已解决问题或补充仍缺失的条件。
4. 核对其他模块是否引用了被改变的规则。
5. 核对链接、术语、数值和实现状态。

这组步骤用于维护文档，不决定游戏开发排期。实际实现后，需要另外记录代码和测试证据，不能只把设计状态改为“已完成”。

## 写作规范采用记录

本轮写作依据 CTC-ZH-001 v0.1《现代简体中文简明技术写作规范》。该规范本身是试行草案，未经读者测试或行业认证。

- 适用范围：本仓库的简体中文设计说明和技术知识库。
- 词汇表：[项目词汇表](glossary.md) v0.1 草案，词条尚待项目审定。
- 表达重点：保留条件、范围、数量、状态、否定和不确定性。
- 版式：中文正文使用统一标点；文件名和代码标识符保留原字符。
- 数字：物品尺寸用乘号连接，例如 1×2 格；速度用 1× 表示。
- 未采用的建议：本轮没有另行登记的项目例外。
- 已批准的表达例外：无。

本轮文本经过设计来源对照、术语检查和链接检查。未运行游戏测试，也未验证架构或数值平衡。词汇表和完整执行规则仍待确认，因此不声明已完成标准要求的全部审定或获得外部认证。
